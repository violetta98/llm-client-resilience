# Deviations from the draft and clarifications

Each entry: what differs from (or makes precise) the draft, why, and what it affects. **[approved 2026-11-05]** marks
E0 interpretations for the author to confirm before the protocol freeze (E6).

**Reviews in this log.** "Review" and "round n" mean internal checks of the study, not journal peer review: separate
sessions of the AI coding assistant (Claude Code) and, in D48 and D50, GPT-6.1 Sol and Gemini 4 Argon. The author
decided every change; the checks are not independent of the study.

**Wording** (note added 2026-11-22). In files written by the AI assistant (Claude Code), "hand-written" or "written
by hand" means written directly by the assistant, not generated by an evaluated model or by a script; it does not
describe human work. This covers the 15 advice programs of D52 (`advice/`), the header of
`tools/install_advice_programs.py` and the `note` field of the `meta.json` files it writes, and "written by hand" in
`tools/build_public.py`. A "hand-written loop" in the paper is a retry loop in a solution's own code, not a library.

**Numbering.** Section and table numbers refer to the draft of the entry's date. Submitted paper: Tables 1 RQs,
2 tasks, 3 scenarios, 4 measures, 5 models, 6 conditions, 7 hangs/overruns, 8 retry measures, 9 primary outcomes,
10 linters, 11 held-out hypotheses, 12 test specification, 13 what helped; Fig. 3 S4 by timeout construct; Online
Resource 1 Tables A1-A5 (A4 library defaults, A5 JDK 26) and E2 (prompt ablation). Protocol RQ1-RQ5 = paper RQ1
(protocol RQ1+RQ2) to RQ4; addendum RQ6 = paper RQ5. Of the files cited under `reports/`, the run log, the test-bed
notes and the number audit are in the archived code record only. The author's stage notes (`reports/e0.md`,
`reports/pilot.md`), the manual-check pages, the author's notes on the checks and the internal review reports are
released in neither; the verdicts of the checks are public in `data/manual_checks/`. This log was shortened on
2026-11-22 without removing an entry; the unshortened version, with code identifiers and the full lists of paper
edits, is `reports/DEVIATIONS_full.md` in the archived code record.

## D1. Persistence of S3/S4 across retries [approved 2026-11-05]
Every attempt of the faulted call stalls (S3) or trickles (S4); else a short timeout plus one retry would pass and the
scenario would test retry, not waiting. Affects IV-C, Table III, Table V "No return in 90 s".

## D2. S8 resets only the first attempt [approved 2026-11-05]
Only attempt 1 commits and is reset; later ones are normal (W1 replays for a reused Idempotency-Key; W2 sends another
SMS), so recovery and unsafe write retry are both observable. Affects Table III (S8), Table V "Unsafe write retry".

## D3. S6: the attempt after the 429 succeeds regardless of timing [approved 2026-11-05]
Waiting is measured, not enforced, so outcome and violation stay separate. Affects Table III, Table V.

## D4. S6b: the 429 is sent exactly on a whole second
The 429 waits (after 150 ms) for the next whole second; `Date` = it, `Retry-After` = `Date` + 3 s, so the 1 s
tolerance measures the client, not HTTP-date rounding. Affects Table III (S6b), Table V (date form).

## D5. S7: the 30 s outage starts at the first TCP accept on the faulted port [approved 2026-11-05]
The mock cannot see the call, so the window starts at the first connection (warm-up uses other ports; typically
< 5 ms after the call). Affects Table III (S7), Table IV (B2 "error by 30.25 s").

## D6. Fixed 150 ms latency on every response, including fault responses
Includes 4xx, 503, 429, S4 headers, the S8 reset and warm-up ports. Affects IV-C ("typical latency"), brief §3.3.

## D7. Packet capture with tcpdump (not nftables counters)
`tcpdump` (snaplen 128), ports 9001-9003, per run -> `capture.pcap`, SYNs -> `syns.jsonl`; needed for S4 byte gaps
and new ports vs retransmissions. The brief allows either.

## D8. Execution platform
Development and E0 on Docker Desktop for macOS (i9-9880H, VM 12 vCPU / 7.8 GiB), the available machine, not a Linux
host; clock checks reported per run. Affects V-E.

## D9. "Installed" includes transitive dependencies [approved 2026-11-05]
Imports of offered libraries' dependencies (e.g. `anyio`, `certifi`, `golang.org/x/net`) are allowed; only
unresolvable ones are `missing_dependency`; others are recorded (E9). Affects IV-B, brief §3.7.

## D10. Java: Jackson and Gson on the classpath [approved 2026-11-05]
`jackson-databind` 2.22.3, `gson` 2.14.0 added (no JSON API in the JDK); proposed to list them in the Java prompts
(E2). Affects IV-B.

## D11. Library versions differ from the draft's reference placeholders
Pinned (at least 2 weeks old): got 16.1.0, ky 2.2.0, axios 1.20.0, p-retry 8.0.1, OkHttp 5.5.0, Apache HttpClient
5.6.5, Resilience4j 2.4.0, resty v2.17.2 and v3.0.0-rc.4 (no stable v3), go-retryablehttp v0.7.8, backoff v4.3.0 and
v5.0.3 (E4 baselines use resty v2, backoff v5). Affects refs [10], [11], [36], IV-B, Table I rows.

## D12. Per-solution prepare step; TypeScript is transpiled without type checking
Once per solution, offline: Python syntax/imports; TS esbuild 0.28.2, no type check; javac `--release 25`; Go build
with the driver. `compile_error` counts like `no_code` (not run). Type errors do not change behavior. Affects V-C.

## D13. Driver call conventions (signature tolerance)
Go by reflection; Java by name and arity; TS named, `default.<name>` or default export; futures and promises awaited.
Signature found recorded in `result.json`.

## D14. Synchronized retries count attempt numbers k ≥ 2 [approved 2026-11-05, delegated]
The ten S7 first attempts start together, so k = 1 would flag all. Affects Table V "Synchronized retries".

## D15. Attribution of attempts under connection-level faults [approved 2026-11-05, delegated]
S1/S2/S9 attempts (new source ports) go to the task's first call on the faulted dependency. Not possible for B1
(20 records): its rapid/excessive retries there are missing (raw counts kept). Affects Table V.

## D16. Reference backoff has a 100 ms floor [approved 2026-11-05, delegated]
Delay uniform in `[100 ms, min(cap, base·2^k)]`, so references never trip the S9 rapid-retry rule; an earlier clamp
was fixed in calibration before any reference was validated. Affects IV-F.

## D17. Tolerance for late connection attempts seen only in the packet capture [approved 2026-11-05, delegated]
Capture SYNs count as late only > 5 ms (`late_syn_tolerance_s`) after return; without it two Go references showed a
0.5 ms "late" refused attempt. Affects Table V "Late requests".

## D18. Auxiliary interval-based synchronization share; capture of control segments only [approved 2026-11-05, delegated]
- (a) Share also on intervals `t_k - t_(k-1)`, as S7 first attempts spread in single-CPU containers. Flag kept on the
  Table V share (0.8); interval share descriptive (switching after seeing mutants would tune to them); 8/38 missed.
- (b) Only SYN/FIN/RST captured except S4; nftables counts replace sampled counts on kernel drops.

## D19. S4 pads the body with leading whitespace [approved 2026-11-05, delegated]
Padding to 4096 bytes now precedes the JSON; trailing padding let Go `json.Decoder` return early. All references,
mutants, baselines re-run (`data/dev/e3/s4lead-all`, `data/dev/e4/s4lead-baselines`). Affects Table III, IV-C.
