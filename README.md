# Timeout and Retry Anti-Patterns in LLM-Generated Code: Benchmark and Analysis Code

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24447081.svg)](https://doi.org/10.5281/zenodo.24447081)
[![Protocol DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24012023.svg)](https://doi.org/10.5281/zenodo.24012023)

Code and summary data for the paper *A Timeout Is Not a Deadline: An Empirical Study of Timeout and Retry
Anti-Patterns in LLM-Generated Code* (manuscript, 2026, under review).

Eight LLMs wrote 3,072 solutions to 16 HTTP client tasks in Python, TypeScript, Java and Go, with and without explicit
resilience requirements. The 2,531 runnable solutions ran against a mock service that stalls, fails, rate-limits or
resets the connection, and we measured whether each call returns in time and retries safely. The default calls of 15
HTTP client libraries ran under the same faults. The protocol was deposited before generation
([10.5281/zenodo.24012023](https://doi.org/10.5281/zenodo.24012023)); `DEVIATIONS.md` lists every change to it.

## Main results

- When the response body arrives one byte every 2 s, 34.8% of the baseline solutions do not return within 90 s:
  2.2% of those with a deadline on the whole call, 73.7% of those whose timeouts only bound each read.
- Explicit requirements reduce these hangs but make retries more aggressive.
- Bandit and Ruff flag about 1% of the failing Python solutions.
- Given a report of the failed fault tests, models fix 79.3% of their failing solutions.
- The main findings hold on four held-out tasks.

`reports/results.md` gives the numbers with their files. `testkit/` is a runnable version of the paper's fault-injection
tests (Table 12) for Python.

## Authorship and AI assistance

The code in this repository was written with Claude Code (Claude Opus 5.5) from the author's specifications and under
the author's direction. The author designed the tasks, faults, correctness criteria, thresholds and analysis, approved
every deviation, and checked the output by hand (100 solutions labeled blind, 35 runs, the measure code, 49 hard cases).
Two Claude models are among the evaluated LLMs; all models are scored by the same code. See Sects. 5.5 and 9.2 of the
paper and Online Resource 1, Sect. A. "Hand-written" in code comments means not generated by an evaluated model.

## What is where

```
tasks/          the 16 tasks: specifications, prompts, correct behavior
mock/           fault-injecting mock service (Go)
runner/         language drivers, Dockerfiles, run orchestration
gen/            generation, code extraction, repair and ablation prompts
references/     64 reference solutions that meet every criterion
mutants/        166 mutants of the references, each removing one property
baselines/      default calls of the 15 HTTP client libraries
classify/       classifier (library, timeouts, retries), linter runs, codebook
analysis/       measures, models, tables, figures (analysis/out/README.md maps outputs to scripts)
protocol/       frozen protocol, addenda, thresholds, freeze hashes
advice/         programs using the recommended constructs (Online Resource 1, Sect. D)
docs_examples/  the libraries' documentation examples
testkit/        fault-injection tests for Python
pilot/          pilot tasks (not part of the results)
tests/          unit and end-to-end tests
tools/          number check, packaging, run viewer
data/           summary data (data/README.md)
figures/        paper figures, PDF and PNG
reports/        results.md and environment versions
certs/          test-only certificates for the mock; never install them elsewhere
```

## Getting the data

The files in `data/` are enough to check every table. The raw runs (0.95 GB) are in the Zenodo data record
([10.5281/zenodo.24447083](https://doi.org/10.5281/zenodo.24447083), CC BY 4.0). Go binaries are not included; they are
rebuilt from source.

```
R=https://zenodo.org/records/24447083/files
curl -L -o llm-client-resilience-data-v1.tar.gz "$R/llm-client-resilience-data-v1.tar.gz?download=1"
curl -L -o SHA256SUMS "$R/SHA256SUMS?download=1"
shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf llm-client-resilience-data-v1.tar.gz --strip-components=1
```

## Reproducing the paper

`make check` recomputes the key numbers from `data/` in under a minute, without Docker, and fails if any differs from
the paper. Everything else needs Python 3.11+, Docker 24+ and the raw data:

```
python3 -m pip install -r requirements.txt
make images     # pinned images: mock, four runtimes, linters, R
make test
make analyze    # paper tables -> analysis/out/main/paper/
```

| Paper item | Script (in `analysis/` unless noted) |

## Limitations

All runs used one host (MacBook Pro, Intel Core i9-9880H, Docker Desktop VM with 12 vCPU and 7.8 GiB; one CPU and 1 GiB
per solution container), so timing measures with 50-100 ms thresholds carry some noise. Sampling used provider defaults.
The tasks are single functions; HTTP/2, gRPC and coding agents are not covered. See Sect. 9 of the paper.
